# Roadmap

## Committed MVP

- Platform foundation, Principal/permission model, Action/Capability Registry and Context Engine.
- Native Ara for staff: Ask/Draft/limited Act with evidence.
- OpenClaw default runtime through provider-neutral AI Gateway.
- MCP `2026-07-28` curated server with scoped clients.
- Client Portal Ara.
- Chatwoot human handoff and safe support references.
- OpenBao machine-secret boundary and Vault-safe metadata/capability use.
- Module SDK, audit, usage, health, failure states and updater architecture.

## v1.0 production completion

MVP hardening plus broader Perfex-core resources/actions, client-safe self-service, first cross-module registrations, Attention baseline, release/updater automation, migration/rollback runbooks, full test evidence.

## v1.x

- More module integrations and provider-neutral resources.
- Better Attention/Home briefings.
- Watch conditions and explicit policy actions.
- Approval Workflow integration for sensitive actions.
- Saved views/usage/cost controls.
- Richer evidence/provenance UX and searchable AI activity.
- Module developer diagnostics and contract validation.
- Optional fallback/runtime adapters where operationally justified.

## v2 / advanced vision

- General automation authoring using registered deterministic actions/events.
- Natural-language save-as-automation preview.
- Long-running MCP Tasks extension.
- Multi-agent specialist delegation in OpenClaw behind one Ara identity.
- Advanced investigations across monitoring, communications, projects and billing.
- Controlled bulk action preview/dry-run.
- Cross-channel continuity where identity and privacy boundaries are strong.
- Advanced analytics and recommendations grounded in deterministic evidence.

## Exploratory only

- Voice-first assistant.
- MCP Apps UI surfaces.
- Local/offline model runtime.
- Cross-installation federation.

Exploratory items are not commitments and must not distort MVP architecture.

## Explicitly rejected / superseded

- Direct database MCP server.
- One model-provider SDK embedded across modules.
- A standalone generic chatbot page as the primary experience.
- OpenClaw as an irreplaceable business dependency.
- Perfex as a second new-support conversation/message source of truth.
- Generic Vault secret reveal/export tools.
- Email-address-only external identity mapping.
- Direct module-to-module table reads as the normal integration pattern.
- Rewriting published Git tags/releases.
